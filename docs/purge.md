# Purge

The `purge` command (DFM-34, `purge <trial>` in DESIGN.md section 7) ends a trial that is not adopted. It removes what the trial added: the package, the Homebrew dependencies that its install added, and the configuration and data paths that were absent before the trial. Then it removes the trial record, so the tool can be tried again. The trial and its record are in [docs/trial.md](trial.md). The design is `docs/superpowers/specs/2026-10-31-purge-design.md`.

## The command

```
dfm purge <trial-id> [--preview] [-y|--yes-plan <digest>]
```

`<trial-id>` is the record's id. A tool name also works when the trial has the default id `trial-<tool>` (`dfm purge atuin`).

A script trial (`dfm trial --script`, docs/trial.md) has no package. Purge reads its observation window instead (see "Script trials").

## What purge does with each item

| Item | Action | Kept when |
| --- | --- | --- |
| The package (`package.adapter`, `package.name`) | `brew uninstall --formula --force <name>` (every keg) or `--cask <name>`, or `mise uninstall --all <tool>`: every installed version. A pinned mise trial (`node@22`) removes only the installed versions that its pin matches (`mise uninstall node@22.1.0`), so another version that predates the trial stays. A listing after the uninstall must not name it. | The tool existed before the trial (`tool_preexisting`). Another active trial names the package (Homebrew names compare by formula: `atuin` and `homebrew/core/atuin` are one package; mise names compare by tool: `node`, `node@22` and `node@22.1` can share an installed version). The provider's listing shows another owner. |
| The Homebrew dependencies (`package.install.dependencies`) | One `brew uninstall --formula --force <dep>...` call for all of them, after the package. Every brew call sets `HOMEBREW_NO_AUTOREMOVE=1`, so brew removes nothing that purge does not name. Homebrew checks dependents against the whole set. When it refuses, each dependency is tried alone once. | Another active trial names it. Homebrew refuses it because an installed formula still needs it (its error says "because it is required by"). That is a kept item (`current`), not a failure. Any other brew failure (its lock, a permission, a timeout) fails the run and keeps the record. A name that starts with `-` is refused before brew runs. |
| A recorded path (`baseline.paths`, `baseline.data`) that was absent before the trial and is present now | Removed: a file, or a directory with its whole tree. Each parent is opened as a real directory owned by this user (`Dir::open_below`), and nothing below is followed. | The path is a link or a special file. A parent is a link, a file or another user's. A directory in the tree is another user's, writable by group or others, or not writable by its owner, so the removal could not finish. A module in the ledger, or another active trial, records the path or a path below it. The tree holds more than 100,000 entries, or its relative paths take more than 16 MiB to list, or it holds a name that is not UTF-8. It cannot be read. A directory that holds a kept path (for example a recorded link) is printed as `retained:` and is not removed as a tree. So is a directory that a kept or retained link points into or at (a relative target is joined to the link's directory, and `.` and `..` are resolved by text; the target and the directory are also compared with every link on disk resolved, so a target through an alias such as `~/.alias -> ~/.config` counts): `retained: <dir> (the kept link <link> points into it)`. Removing it would leave that link dangling. |
| A recorded path that existed before the trial | Nothing. | Always: "existed before the trial", changed or not. |
| `unknown` effects | Nothing. | Always: printed as `retained:`. |

Purge asks only the provider's own listing (Homebrew's Cellar and Caskroom, `mise ls --installed`), not the install-planning checks of `packages`. A listing that cannot answer refuses the whole purge with `E_PROBE_FAILED` before any change. So does another trial record that cannot be read (`E_STATE_INVALID`): it could name the same package or path. Removing the record then would lose the only evidence of what the trial installed.

## Script trials

A script trial records `script.window`: each watched path that the run `created`, `modified`, `removed` or changed in kind (`kind-changed`). Purge decides from those entries, after the record's `baseline.paths` and `baseline.data` as above. A window entry that is also a baseline path is decided once, as a baseline path, unless a rule below retains it: a retained path is never removed, so its baseline item is dropped (for example a plist in `~/Library/LaunchAgents` given as `--config`). Every path comparison in these rules (`script.before`, the baseline paths, the watched places, `~/Library/LaunchAgents`, HOME, created directories, kept and retained paths, and other trials' paths) uses the case fold of the ownership checks. On a case-insensitive volume a case-only rename (`~/bin/Keep` to `~/bin/keep`) is a `removed` and a `created` entry for one file, and the `created` one is in `script.before`, so it is retained. Unicode normalization is not folded, and the same-file guard covers a rename that only changes normalization: a `created` path is retained when some `removed` entry of the same window still resolves to the same file (equal device and inode from an `lstat` of each; if either `lstat` fails the guard does not apply), with the reason `retained: <created> (the same file as <removed>, which existed before the trial; renamed during the trial)`.

| Window entry | Action | Kept when |
| --- | --- | --- |
| `created` directory or regular file below HOME | Removed, as a recorded path that was absent before the trial: the same tree rules, ownership checks and limits. A created directory that holds a kept or retained path, a kept recorded path included, is not removed as a tree (the kept path is also compared with the links among its parents resolved, so `~/.alias/boat/rc` with `~/.alias -> ~/.config` holds `~/.config/boat`): it is printed as `retained: <dir> (holds <path>, which is kept)`, and the other candidates in it are still removed one by one. The digest covers its live fingerprint, whatever its content is now. Under the lock, and again just before each removal, when an entry is no longer the kind or the fingerprint the decision saw (a file's content, a tree's paths, kinds and sizes, a link's target text), that path is not removed (`E_PLAN_STALE`); actions earlier in the same run stay done and the run exits 1. | The kept rules of a recorded path. It is now another kind than the window saw (`retained:`). It is a path of the manager, or overlaps a guarded checkout or the directory of the dfm executable (`retained:`). The record's `unknown` holds `window-truncated`: the window may omit what a directory holds, so no directory is removed as a tree, whether a window entry or a recorded path (`baseline.paths`, `baseline.data`) names it, and each is printed as `retained: <dir> (the window was truncated; its contents were not all recorded)`. A link that only such a directory vouched for is then kept. The created files and links that the window lists stay candidates. |
| `created` link below HOME | Removed with `unlink`, never followed. The digest covers its target text. Under the lock, the link is removed only when its target text is still the one the preview saw. | Its target is not the recorded target and does not lie inside (or is not) a created directory that purge removes: one that passed every rule above, is not retained, and is an `action: remove`. A created directory that is held because it holds a kept path (`retained: <dir> (holds ...)`) vouches for no link: a link that only it authorized is printed as `kept: <path> -> <target> (points into <dir>, which is kept)`. Keeping that link can hold another directory, so purge repeats both rules until neither changes. A relative target is joined to the link's directory and resolved in the order the kernel walks it: each existing component is followed through its links, so `..` after a linked component leaves where that link led, and only the missing tail is joined by text (a missing name is not a link). A link on the way that does not resolve authorizes nothing. It is printed as `kept: <path> -> <target> (repointed since the trial)`, or `(no target recorded)` when the window has no target for it. A link whose target is not UTF-8 is always kept: `keep: ... its target is not UTF-8, so it cannot be compared` (its shown form could match a different target). |
| `created` entry in `~/Library/LaunchAgents` | Nothing. | Always: `retained: <path> created during the trial; unload it with launchctl bootout gui/<uid> '<path>', then remove it by hand`. The path is single-quoted, so the pasted command passes it as one word. |
| `modified` file | Nothing. | Always: `retained: <path> modified during the trial (sha256 <before> -> <now>); edit <path> by hand`. `<now>` is the live SHA-256 (through a link), or `none` when the file is gone, too large or unreadable. `<before>` comes from the entry, or from `script.before` when a shrunk window dropped it. A link also shows `target <before> -> <now>`. |
| `removed` or `kind-changed` entry | Nothing. | Always: `retained: <path> <change> during the trial; never restored`. |
| `created` entry outside HOME | Nothing. | Always: `retained:`. The sandbox denies writes outside HOME, so this is evidence only. |
| `created` entry of kind `unreadable` | Nothing. | Always: `retained: <path> could not be read after the run; never removed`. |
| `created` entry of kind `other`, or a path that holds U+FFFD | Nothing. | Always: `retained: <path> (the name was not recorded exactly)`. The window records a name that is not UTF-8 or holds a control character by a shown form that can name another file, and gives it the kind `other`. A special file has the kind `other` too, and is retained the same way. |

The window is evidence, not authority. A `created` entry is never removed, and is printed as `retained:`, when `script.before` holds its path, when its parent is `unreadable` in `script.before` (what was in that place before the run is not known), or when no watched place could have reported it: it is not a watched file, and its parent is not a watched directory or listing (docs/trial.md, "Script trials").

Another active script trial protects what it changed. A recorded path or a window candidate is kept (`keep: ...: trial <id> observed <path>`) when an entry of that trial's window (any change) is the candidate, lies below it, or lies above it (for example a file that trial turned into a directory). A path that trial changed after this one created it is therefore never removed while that trial is active. A path that trial only observed in `script.before` does not keep the candidate. When that trial's run did not finish (no window), or its record holds `window-truncated`, what it changed is not all recorded: it may have created a path again after its `script.before`. Purge then removes no candidate: no window candidate and no baseline path (`baseline.paths`, `baseline.data`), for a package trial as for a script trial. Each one is printed as `retained: <path> (script trial <id> is incomplete; what it changed is not recorded)`. When that trial is complete, a baseline path keeps the rules above, and every path in that trial's `script.before` counts for it as well, when it is the baseline path or lies below it.

The `unknown` tokens of the record (`script-downloads`, `later-self-updates`, `keychain`, `remote-effects` and the rest) are printed on the `retained:` line, as for a package trial. Every `retained:` line is in the digest.

A record with `before`, no `window` and no `exit` is a run that did not finish (a crash, a SIGKILL, a sleep). A record with an `exit` and no `window` is a run that ended but whose after-observation failed (a cap, for example): what changed during the run is unknown and a live diff would also count what appeared since, so no window candidate is removed (`retained: window candidates (the run ended but its after-observation was not recorded; nothing it created is removed)`). Its baseline paths keep their own rules. For a run that did not finish, purge then observes the watch set again, with the record's `script.env` for `ZDOTDIR`, and compares it with `before`. Each entry created since `before` is a candidate, with the same rules. A path created after the run ended is a candidate too: the preview lists it, and the digest is the approval. Such a diff has no recorded link target, so a created link is removed only when its target lies inside a created directory; any other is `kept: ... (no target recorded)`. The preview prints `note: the script run of this trial did not finish; each path created since its before observation is a candidate`.

## Order of one run

1. **Decision.** The record is read (`E_STATE_INVALID` when it is missing or unreadable, `E_CONFLICT` when it is adopted, `E_IDENTITY_MISMATCH` when it was written for another profile or machine). The providers are probed, the paths are observed and the other active trials are read. The preview prints one `action:`, `keep:` or `nothing:` line per item, the `retained:` line and `plan digest:`. The digest covers every item and its step, the fingerprint of each present path (a file's SHA-256, or its size above 16 MiB; a directory's entry count, bytes and the SHA-256 of every relative path, kind and size), the binary identity and the binding.
2. **Approval.** `--preview` stops here (exit 0). Without `--yes-plan` the run stops with `E_APPROVAL_REQUIRED` (exit 3).
3. **Under the lock.** The writer lock is taken and the decision is made again. A digest that differs is `E_PLAN_STALE` (exit 3, nothing changed).
4. **Actions.** Each action has its own journal operation id, `purge-<ns>-<pid>-<n>`, with an `intent` before it and a `done` or `failed` entry after it. A stop request starts no new action. A failed package uninstall ends the actions: its dependencies and its files stay while the package may still be there. Another failed action stops nothing that follows. A recorded path below a directory that this run removed went with that tree and gets no action of its own. Each removal intent names its path, so `dfm state recover` can settle an interrupted removal.
5. **The record.** When no action failed, the record is removed last: `trial: state/trials/<id>.json removed`. When one failed, the record stays and the run exits 1. Run `dfm purge <id>` again after the fix: the second run decides from the live state, so done steps show as `nothing:`.
6. **The receipt.** `command = purge`, one operation per action, `plan_digest` and a `yes_plan` approval.

| Exit | When |
| --- | --- |
| 0 | Every action succeeded or was kept, and the record is removed. |
| 1 | An action failed after a change. The record stays. |
| 2 | Usage. |
| 3 | Blocked before any change: approval missing, stale digest, missing or adopted trial, probe failure, lock held, not bound. |
| 130, 143 | A stop request. |

## Known limits

- **Data paths are a fixed list.** `trial` observes `~/.local/share/<tool>`, `~/.local/state/<tool>`, `~/.cache/<tool>`, `~/Library/Application Support/<tool>` and `~/Library/Caches/<tool>` (docs/trial.md). A tool that writes elsewhere needs `--config` at trial time. A trial recorded before this change has no data baseline. Its preview prints a `note:` line, and only its configuration paths are covered.
- **No restore.** A path that existed before the trial is kept as it is now. The trial keeps a hash, not the content, so purge cannot restore an earlier version.
- **No source tree.** Purge reads no module. A package that a module also declares by hand is uninstalled, and the next `sync` installs it again.
- **Not an OS sandbox.** Services, logs and paths outside the recorded ones are `unknown` and are never cleaned.
- **Dependency of a kept dependency.** When Homebrew refuses the combined call, each dependency is tried alone once. A dependency that only another trial dependency needs can then be kept, and it is reported.
- **Evidence scope.** Tests use the `test-isolation` build and the `brew` and `mise` look-alikes. No test runs a real uninstall.
