# DFM-25 C01 slice 1: uv-tool sources and gated mise Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** dfm installs token-auditor (git source at a tag) and agent-reap (path source in the bound checkout) as `uv-tool/v1` resources, and the `mise` updater runs `mise install` and `mise upgrade` only when every non-registry backend tool has a grant.

**Architecture:** `uv-tool/v1` gets an optional `source` field. A source tool is probed from uv's receipt and installed with `uv tool install --force <source>`; a git source needs an origin grant, read through the existing `ScriptCx` state view. The `mise` updater reads the global mise config without running mise, maps backend tools to identities, and blocks before any mise command when one has no grant. A new `go:<module>` identity is stored with the `npm:` grants.

**Tech Stack:** Rust (workspace crates `dfm-model`, `dfm-cli`), `toml`, the engine `Runner`, shell look-alikes in tests.

**Spec:** `docs/superpowers/specs/2026-11-11-dfm-25-c01-side-channels-design.md` (slice 1 of "Delivery"; sections "Package adapters" (`uv-tool/v1` sources), "Updaters" (`mise`), "mise sources").

## Global Constraints

- A pin is data in a bundle document; nothing in Rust names token-auditor, agent-reap or a tag (G3).
- A document cannot add a command (G4): the only new command forms are `uv tool install --force <source>` and `mise install`.
- One ungranted identity blocks the whole `mise` row before any mise command, one note per identity (spec, "mise sources").
- An ungranted note reads `E_SOURCE_UNTRUSTED: no grant for <id>; review it, then run dfm sync --trust-origin '<id>'` (the existing `untrusted()` helper).
- `uv-tool/v1` `name` stays a package-index name; `source` is optional, and a value without it behaves exactly as now.
- Commit messages: Conventional Commits, no attribution lines. Run the gate on the branch head only (`just check`), not per commit.
- Prose in docs follows the existing docs' style; no em or en dash as a separator.

## Change to the approved spec (owner review needed)

The spec maps `go:<module>` to a GitHub origin and refuses other hosts. The live global config declares `"go:golang.org/x/tools/gopls"`, so that rule blocks the `mise` row on every sync. Task 1 replaces it: `go:<module path>` is its own identity, granted with `--trust-origin 'go:golang.org/x/tools/gopls'` and stored in `packages` beside `npm:`. Registry short names (`go`, `java`, `rust-analyzer`) are not gated: mise's registry is the owner, as Homebrew's official formulae are. Task 1 also edits the spec's "mise sources" section to say this.

## Review Focus

1. A git `source` whose ref is a branch name (`main`) must be refused at probe time, never installed. (Task 3, `a_git_source_with_a_branch_ref_is_refused`.)
2. A `path:` source that leaves the bound checkout through `..` or a symlink must be refused. (Task 3, `a_path_source_outside_the_checkout_is_refused`.)
3. A tool installed from the same git URL at another rev must read as missing and be installed again. (Task 3, `a_git_source_at_another_rev_is_missing`.)
4. A mise tool key with options (`"ubi:o/r[exe=x]"`) must map to the repository identity without the options. (Task 2, `mise_identities_strip_tool_options`.)
5. No global mise config at all must leave the `mise` updater ungated and running as now; an unreadable or invalid config must block with the file named. (Task 2, `mise_without_a_global_config_is_not_gated` and `mise_with_an_invalid_config_is_blocked`.)
