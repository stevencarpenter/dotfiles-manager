# DFM-25 C01 slice 2: declared git checkouts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `dfm sync` clones each declared git checkout (tpm, the agent registry) when it is missing and fast-forwards it to its default branch on every run, with no grant for a checkout the owner declares.

**Architecture:** A new `git-checkout/v1` package adapter probes and clones (packages scope). A new `checkouts` updater fast-forwards every declared checkout after the scopes, reusing the `agents` updater's fast-forward flow, which moves into a shared helper. The updater environment carries the declared checkouts from the resolved profile. The `agents` updater needs no grant when its managed copy is a declared checkout from the same repository.

**Tech Stack:** Rust (`dfm-model`, `dfm-cli`), the engine `Runner`, git look-alikes in tests.

**Spec:** `docs/superpowers/specs/2026-11-11-dfm-25-c01-side-channels-design.md` ("Package adapters": `git-checkout/v1`; "Updaters": `checkouts`, `agents`; "Delivery" slice 2), with the owner decisions of 2026-11-12 (stored in the spec's decision section by slice 1): user experience first; a source the owner declares in the owner's own checkout needs no grant; everything rolls to its newest version, so a checkout follows its default branch.

## Global Constraints

- A declared checkout needs no grant (owner decision 2026-11-12). Discovered sources keep their existing grant checks.
- A checkout follows the branch its clone tracks; dfm never pins a revision, merges, resets, rebases or force-updates.
- A dirty, diverged or upstream-less checkout is left as it is and reported `blocked` in its note; the other checkouts still run.
- The packages scope only clones a missing checkout; it never pulls.
- A document cannot add a command (G4): the only new commands are `git clone [--branch <b>] <url> <path>` and the existing fast-forward sequence.
- Commit messages: Conventional Commits ending in "(DFM-25 C01)", no attribution. Gate the branch head only.
- Docs prose: short sentences, no em or en dash as a separator.

## Review Focus

1. A path that exists but is not a git checkout (a plain directory, or a file) must be reported as another owner, never cloned into or deleted. (Task 1, `a_path_that_is_not_a_checkout_is_another_owner`.)
2. A checkout whose origin is another repository than declared (`https` vs `ssh` forms of one repository count as different) must be another owner, not "current". (Task 1, `a_checkout_of_another_repository_is_another_owner`.)
3. A `path` that leaves HOME (`../x`, absolute) must be refused at resolve time. (Task 1, schema `HomePath`.)
4. One blocked checkout (dirty) must not stop the fast-forward of the others in the same `checkouts` row. (Task 2, `one_dirty_checkout_does_not_stop_the_others`.)
5. A declared checkout that is not cloned yet (first sync on a new machine, packages scope blocked) must be a note, not a failure. (Task 2, `a_checkout_not_cloned_yet_is_a_note`.)

  `pub(crate) fn probe(runner: &Runner, value: &Value) -> Result<PackageState, Refusal>`,
  `pub(crate) fn install(runner: &Runner, value: &Value) -> Result<(), Refusal>`.
- Schema: `field("url", Schema::Str, true)`, `field("path", Schema::HomePath, true)`, `field("branch", Schema::Str, false)`; kind `package`, `TargetRule::Forbidden`, `Claims::None`. `update_policy` is not a field.

- [ ] **Step 1: Write the failing tests.** Unit: `declared` accepts `https://github.com/o/r(.git)`, `git@github.com:o/r.git` and `ssh://git@github.com/o/r`; refuses a `file://` URL, a local path and a URL with userinfo other than `git@`; a `branch` with whitespace, a leading `-` or `..` is refused (all `E_MANIFEST_INVALID`). Integration (`crates/cli/tests/packages.rs`):
  - `a_missing_checkout_is_cloned`: plan lists an install; the run logs `git clone https://github.com/o/r.git <HOME>/x/r` (the URL exactly as declared); the next plan is current.
  - `a_branch_is_passed_to_the_clone`: `branch = "main"` logs `git clone --branch main ...`.
  - `a_checkout_of_the_declared_repository_is_current`: `.git` exists and `remote.origin.url` is `git@github.com:o/r.git` while the declaration is `git@github.com:o/r.git`: current, no clone.
  - `a_checkout_of_another_repository_is_another_owner`: origin `https://github.com/o/other`: `E_CONFLICT`, no clone.
  - `a_path_that_is_not_a_checkout_is_another_owner`: a plain directory and a regular file at the path: `E_CONFLICT`, nothing written.
- [ ] **Step 2: Run** `cargo test -p dfm-cli --features test-isolation --test packages checkout` and expect FAIL.
- [ ] **Step 3: Implement.** Identity comparison uses `dfm_model::lock::git_identity(value, cfg!(feature = "test-isolation"))` on both the declared URL and `git -C <path> config --get remote.origin.url` (run through the runner; no network). States: no path → `Missing`; path is a git checkout with the same identity → `Installed("<short HEAD>")` (`git rev-parse --short HEAD`); anything else at the path → `OtherOwner(<reason naming the path and the origin found>)`. Install: create the parent directory, then `git clone [--branch <b>] <url> <HOME>/<path>` with `GIT_TERMINAL_PROMPT=0`, the install timeout, and no other environment; a failed clone removes nothing it did not create.
